# Hub API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (this project forbids subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve per-repository health and the weekly report to the hub through a service-binding-only `HubApi` entrypoint, read-only and fail-closed.

**Architecture:** A pure core in `src/steward/hub/` (snapshot types, text safety, health and report projections, request checks, a cached service), a GitHub reader in `src/steward/github/hub_client.py` (one aliased GraphQL query with a read-only token), and thin Workers adapters: `HubApi` (named entrypoint) and `HubData` (one Durable Object holding the cache and the report).

**Tech Stack:** Python 3.14 on Pyodide (Cloudflare Python Workers), pydantic (strict), pytest + hypothesis, ruff, mypy, pywrangler.

**Spec:** `docs/superpowers/specs/2026-10-19-hub-api-design.md`; threats: `docs/threat-models/2026-10-19-hub-api.md`.

## Global Constraints

- Everything written to the repository is English; no AI trace in code, comments, commits, PRs or the App's output.
- Commits authored as `ismaleonsaenz@gmail.com` (`git config user.email` checked before the first commit).
- Work on `feature/hub-api`, never on `main`; the PR says `Closes #<step-4 issue>`.
- No new dependencies. `pydantic` stays at its pinned version.
- `src/steward/hub/` and `src/steward/github/` import nothing from `workers`; they are tested on CPython.
- Health cache TTL 5 minutes; `HUB_LIMIT` 60 per 60 seconds keyed by the caller; titles at most 200 characters.
- Every `url` matches `^https://github\.com/[A-Za-z0-9-]+/[A-Za-z0-9._-]+(/(pull|issues)/[0-9]+)?$`.
- Every response carries `API_HEADERS`; every error body is exactly `{"error": "<code>"}`.
- Read-only token permissions, exactly: `{"metadata": "read", "pull_requests": "read", "issues": "read", "checks": "read", "statuses": "read", "deployments": "read", "vulnerability_alerts": "read"}`.
- Verification commands: `uv run pytest`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src tests`, `uv run pywrangler deploy --dry-run --outdir .wrangler/dry-run`. On Windows from `D:`, set `$env:UV_CACHE_DIR='D:\.uv\cache'; $env:UV_PYTHON_INSTALL_DIR='D:\.uv\python'` before `pywrangler`.

## Review Focus

1. **No managed repositories** (all archived or ignored): health is `{"generated_at": …, "repositories": []}` and no GraphQL request is sent, since an empty query is invalid. Test in Task 5.
2. **More than 100 open PRs or alerts** (connection truncated): `pull_requests.open` stays the `totalCount`, but `dependabot` and `security_alerts` read `null` rather than an undercount. Tests in Tasks 3 and 5.
3. **Empty repository without a default branch**, or one renamed between listing and query (`repository` is `null`): that entry reads `unknown`/`null`, and the others are unaffected. Test in Task 5.
4. **A stored health entry stamped in the future** (clock jump): treated as stale, never served indefinitely. Test in Task 6.
5. **A repository whose PRs or standards issue could not be read**: the report lists it under `unknown` instead of silently showing nothing pending for it. Test in Task 4.

Contract additions these force, folded into `docs/hub-api.md` in Task 8 and into the spec:
- `pull_requests.dependabot` may be `null`;
- the report gains `"unknown": ["<owner>/<repo>", …]`.
